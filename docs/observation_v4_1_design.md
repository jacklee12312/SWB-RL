# Observation v4.1 结构化输入设计

最后更新：2026-07-28。

## 结论

Observation v4.1 是 v4.0 信息审计后的结构化编码版本。它不修改引擎
`GameState`，不改变规则、随机数或 112 个动作编号，也不扩大 Transformer 和
GRU 的宽度。它解决的是输入组织问题：不再把大量 one-hot 位和局部状态混成一个
大平面，而是把状态交给拥有明确含义的 token 和动作候选编码器。

当前固定规格为：

- 61 个 NumPy 字段（包含 `action_mask`）；
- 15,757 个非卡牌输入；
- 1,290 个共享卡牌词表索引；
- 112 位合法动作掩码；
- 93 个送入 Transformer 的 256 维 token；
- Transformer 4 层、8 头、宽度 256，前馈层 1,024；
- GRU 隐藏状态 512；
- 当前 826 张卡词表下标准网络为 5,581,698 个参数。

v4.0 的 49 字段、55,992 个数值和 418 个卡牌索引仍保持原样，用于恢复已有
模型。v4.1 是独立 schema `observation-v4.1`，不能把 v4.0 checkpoint 的输入
权重直接硬套过来。

## 93 个主序列 token

| token 组 | 数量 | 内容 |
|---|---:|---|
| 对局 | 1 | 当前回合、阶段、行动方、先后手、换牌、待选择与墓场页状态 |
| 玩家 | 2 | 双方生命、PP、EP/SEP、职业、公开资源、累计计数及主战者伤害修改器汇总 |
| 实体 | 19 | 己方 9 张手牌、己方 5 个场面、对方 5 个场面 |
| 主战者区域 | 20 | 双方各 5 个信仰与 5 个纹章 |
| 区域汇总 | 13 | 初始牌表、当前己方牌库、双方墓场/消失区、破坏与登场累计记录 |
| 公开事件 | 32 | 最近 32 个公开事件，保留顺序 |
| 规则记录 | 6 | 双方已破坏随从、已破坏护符、随从登场各一组 |
| 合计 | 93 | 固定长度；空实体和空事件使用 padding mask |

玩家、区域和记录汇总 token 即使当前为空也保留，因为“该组为空”本身是有效
状态。手牌、场面、主战者区域和事件的空槽会被 Transformer padding mask
屏蔽。

## 局部状态如何进入所属 token

### 手牌与场面实体

每个实体 token 由共享卡牌 embedding 加上下列局部信息组成：

- 存在、费用、攻防、进化/超进化、倒数、攻击状态、奥义/解放奥义等基础状态；
- 当前来源与原始来源的离散 embedding；
- 当前有效关键词以及永久增删摘要；
- 费用、攻防、攻击次数、攻击限制、指定限制、关键词增删的逐项 modifier；
- modifier 的类型、子类型、持续时间、到期方和数值；
- 每种 modifier 的数量与溢出位；
- 动态获得的谢幕曲、回合结束能力和随机选择历史；
- 各类动态能力的数量与容量溢出位；
- 融合素材卡牌的共享 embedding 池化；
- 对应监听器的触发次数和本回合已用状态。

modifier 先按种类分别截断，再汇入实体，某一种类超限不会挤掉另一种类。手牌
每槽最多 56 行，场面每槽最多 56 行；每种类另有独立容量和溢出位。

### 信仰、纹章与主战者修改器

20 个主战者区域槽分别携带来源卡、类型、所属方、信仰值与动态能力，或纹章
倒数、逐触发次数、每回合已用状态与随机历史。对应监听器状态加入同一个槽。

双方主战者伤害修改器按玩家分别池化到两个玩家 token，保留模式、持续时间、
到期方、来源控制者、公开来源引用、数值与来源卡。

### 区域和牌库

13 个区域各保存最多 64 组“卡牌索引 + 数量”，并保存被截断的卡牌种类数和
总张数。正常 40 张初始牌组不会触及 64 种上限；该上限主要防止长局中大量生成
卡造成输入无限增长。

己方当前牌库另保存最多 40 个物理卡牌行，包括卡牌身份、当前费用、攻和体。
这些行先按内容排序，所以能表达牌库内变身或永久修改，却不会泄漏抽牌顺序。

### 事件与完整规则记录

最近 32 个公开事件各自成为一个 token，包含事件类型、行动方、公开数值、
来源/目标公开区域引用、来源/目标卡牌身份、过滤后的结构语义和时间位置。

整局累计的已破坏随从、已破坏护符和随从登场记录按双方分成六组。每组保留
最近 16 条详细行并池化为一个 token；13 个区域中的卡名直方图保留窗口外的
累计数量，因此窗口截断不会抹掉“某张卡整局发生过几次”。

## 结构语义 token

动态能力、事件原因、选择模式和随机历史不能用不稳定的 Python 对象 ID，也
不能把原始字符串直接当连续数值。v4.1 先移除 `entity_id`、请求 ID 等运行时
身份，把结构规范化为排序 JSON，再取 SHA-256 的前 32 位。

每个语义行是五个离散值：

```text
(语义种类, 哈希字节 0, 哈希字节 1, 哈希字节 2, 哈希字节 3)
```

网络分别学习语义种类、字节值和字节位置 embedding。它没有把 32 位展开成
32 个平面布尔值。32 位哈希理论上仍可能碰撞；如果对实际规则库的审计发现
碰撞，必须升级 schema 或改为审计词表，不能静默接受。

## 以合法动作为中心的候选

普通选择和墓场选择不会占用 32 个额外主序列 token。每个候选在给对应动作
打分时直接附加：

- 候选卡牌 embedding；
- 当前公开实体引用或主战者关系；
- 是否已选择；
- 墓场来源、派生/衍生状态；
- 选择或离场原因的结构语义。

攻击、打出、进化和超进化继续从上下文化后的来源/目标实体 token 构造动作。
测试锁定了候选置换等变性：交换两个候选及其状态，两个对应动作的分数也必须
交换，而不是把偏好固定在“第一个按钮”。

## 隐私边界

v4.1 永远不输入：

- 对手隐藏手牌；
- 未公开的对手牌库组成；
- 任一牌库顺序；
- 未来随机数；
- 原始 `entity_id`、`source_id`、`target_id` 或请求 ID。

己方当前牌库组成可以输入，但先排序并且没有抽牌顺序。对方初始牌表只有显式
`open_decklists=True` 时才公开。非当前决策方的私有选择字段和合法动作掩码
保持全零。训练时如需对手手牌预测，只能把隐藏信息作为辅助头的监督答案，不能
直接喂给策略主干。

## 版本和迁移

- v3.6、v4.0、v4.1 各自拥有不同的 schema 名称和清单哈希。
- 旧 checkpoint 根据保存的版本严格恢复，不会自动迁移到 v4.1。
- v4.1 只允许 `entity_action_v1`，避免旧平面 GRU 把类型编号和哈希字节当作
  有大小关系的连续数。
- 训练 CLI 默认 v4.1；库级 `PPOConfig` 仍保留 v4.0 默认值，避免没有显式
  版本的旧调用悄悄改变含义。
- 可手工迁移共享卡牌 embedding、Transformer、GRU 和动作头中形状相同的
  权重，但新增的结构投影必须重新初始化；当前 checkpoint 加载器有意不做这种
  模糊的部分加载。

## 当前固定上限与后续判断

- 公共事件：32；
- 每个规则记录组：16；
- 每个区域的不同卡牌：64，并带溢出统计；
- 己方物理牌库行：40；
- 信仰/纹章槽：20；
- 普通选择与墓场页：各 16；
- 实体 modifier：按种类固定容量并带溢出统计。

先用 v4.1 进行吞吐、训练稳定性和消融测试，再决定是否扩大模型。只有当
训练/验证表现显示容量瓶颈，而不是规则、数据分布或优化问题时，才考虑把
Transformer 从 256 扩到 384/512、增加层数或扩大 GRU。

## 初始性能基线

同一台 i7-13700KF / RTX 4080、同一种子和 300 个随机合法动作的环境基准中：

- v4.0：约 261 环境步/秒，冷观察约 429 次/秒；
- v4.1：约 460 环境步/秒，冷观察约 893 次/秒。

因此结构化观察本身更轻。另一方面，标准四层网络的纯 CUDA 前向目前受主序列
长度影响：

| batch | v4.0 决策/秒 | v4.1 决策/秒 |
|---:|---:|---:|
| 1 | 259 | 129 |
| 4 | 1,020 | 501 |
| 16 | 4,181 | 1,996 |
| 64 | 16,739 | 5,420 |

表中是每种配置预热后连续三轮各 100 次前向的中位数。这些数字是前向微基准，
不是完整 PPO 吞吐；但它们明确说明“参数更少”不等于
“推理更快”。v4.1 的 93 个 token 比 v4.0 的 20 个 token 产生更多注意力
计算。后续速度优化应优先测试历史/记录的分层池化、空槽压缩或高效注意力，
同时用消融实验确认没有丢掉长期规则信息；不能仅为了跑分快而退回有字段碰撞的
平面输入。

## 100k 学习有效性消融

2026-07-28 的单 seed 主教专精小规模实验使用同核心网络、同卡组日程和同
PPO 预算比较 v3.6 与 v4.1。约 10k 时 v4.1 对 v3.6 为 47%；约 100k 时
降至 32%（200 局，95% CI 25.9%–38.8%）。面对共同 v3.6 10k 冻结参考的
七卡组 280 局评测中，v3.6 100k 为 86.25%，v4.1 100k 为 81.79%；
配对差值 −4.46 个百分点，bootstrap 95% CI −9.46 到 +0.36，尚未排除零。
v4.1 训练综合吞吐约 71.57 步/秒，v3.6 约 235.99 步/秒。

因此 v4.1 已证明可以稳定训练并学到非平凡策略，但当前设计没有在 100k
小预算下显示学习优势，且计算代价过高。完整协议、逐卡组结果和限制见
[`observation_v3_6_v4_1_learning_ablation.md`](observation_v3_6_v4_1_learning_ablation.md)。
